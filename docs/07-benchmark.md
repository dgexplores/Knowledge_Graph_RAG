# Benchmark results — Phase 5

Committed snapshot of `python -m kg_rag.cli bench --sample`. Regenerate anytime; this file is the
committed record of the last measured run.

**Last measured:** 2026-10-16
**Command:** `python -m kg_rag.cli bench --sample --out bench_report.json` (then committed here)
**Corpus:** 8 synthetic 10-K filings, 16 chunks, 8 graph nodes, 18 edges (offline demo, no API key, no network)

## Headline

| Metric | Value |
| :--- | :--- |
| Hybrid accuracy (overall) | 10/10 = 1.00 |
| Vector-only accuracy (overall) | 2/10 = 0.20 |
| Delta | +0.80 |
| Hybrid p50 latency | ~13 ms |
| Vector-only p50 latency | ~5 ms |
| Citation defects | 0 |

## Per class

| Question class | Hybrid | Vector-only | Gap |
| :--- | :--- | :--- | :--- |
| 1-hop (single fact) | 3/3 = 1.00 | 1/3 = 0.33 | +0.67 |
| 2-hop (one relationship) | 2/2 = 1.00 | 1/2 = 0.50 | +0.50 |
| Aggregation (count over relations) | 2/2 = 1.00 | 1/2 = 0.50 | +0.50 |
| Definition | 1/1 = 1.00 | 1/1 = 1.00 | parity |
| Out-of-scope (must refuse) | 2/2 = 1.00 | 0/2 = 0.00 | +1.00 |

**Parity on 1-hop and a widening gap as hops increase is the entire claim.** The graph beats dense
retrieval on multi-hop questions, matching it on single-hop and definition questions, and refusing
out-of-scope questions instead of answering them.

## Full report

The machine-readable report is `bench_report.json` (regenerated by the bench command; not committed
because it changes with every re-run). It contains per-question correctness, route, citations,
latency, and the strict-scorer details. Scorer: strict substring matching — every expected term
must appear in the answer; partial credit is deliberately not awarded because it rewards answers
that name every entity in the graph.

## Caveats (honest)

- This is a 10-question offline demo corpus, not a production benchmark. The numbers prove the
  retrieval design works; they do not generalize to a real EDGAR corpus.
- `HashingEmbedder` is a deterministic stub; pgvector is wired but not populated with real
  embeddings yet. The "vector-only" baseline is therefore weak by design — it measures retrieval
  over hashed text, not a trained embedding model.
- Real EDGAR ingestion needs `SEC_USER_ACCESS` with a real contact email and is not part of this
  measured run.
